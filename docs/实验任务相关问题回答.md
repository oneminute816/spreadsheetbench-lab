# 实验任务相关问题回答

主数据集为 SpreadsheetBench 原版 v0.1。本周固定选择 `12307`、`15380`、`15829`、`13-1`、`17-35` 五题，用于理解表格任务、接入接口及定位失败。它们是有意选择的办公场景样本，并非对 912 题的随机抽样。

## 五题为何与日常办公相关

| 题目 | 办公场景 | 本周覆盖的操作 |
| --- | --- | --- |
| `12307` | 人员或机构覆盖地区统计 | 按清单与正数条件计数，填写汇总单元格 |
| `15380` | 从文件名或业务编码生成月份字段 | 文本提取、对照表查找、整列填充 |
| `15829` | 按套餐和用量核算月费 | 双条件查价与金额计算 |
| `13-1` | 把分散业务记录合并进报表 | 按日期和编号去重、更新旧数据、汇总金额 |
| `17-35` | 从明细台账筛选日期区间 | 按起止日期过滤并写入指定区域 |

## 六个问题

### 1. 这个数据集是想要测试什么的？

SpreadsheetBench 测试 Agent 能否把自然语言中的电子表格修改要求落实到工作簿，并把解法迁移到同题的其他输入。它同时涉及理解工作表结构、定位目标区域、选择公式或脚本、保存可用工作簿。本周适配器要求 Agent 生成可复用的 `solution.py`，这是我们的实验实现；其结果不能直接称为官方榜单成绩。

### 2. 这个数据集的任务输入输出是什么？给出一到两个示例。

每题包含英文修改要求、`answer_position` 和三个编号输入/参考答案工作簿。Agent 只接收要求和用例 1 的 `input.xlsx`，输出 `solution.py` 与 `output.xlsx`。评估阶段把同一脚本用于用例 2、3，生成 `2_output.xlsx`、`3_output.xlsx`，然后才读取参考答案。

- `12307`：输入表含国家清单、公司和各国雇员数；要求统计雇员数大于零且在清单内的国家数，写入 `I12:I13`。输出是填好的工作簿及可重复运行的脚本。原生评分位置为 `I12:I13`，三例逐一比较。
- `15380`：输入的 `A3:A14` 是包含月份代码的文本，工作簿内另有 `codes2` 与 `month` 对照；要求填好 `B3:B14` 的月份值。例子 `2014_09_Drop2_Reminder` 对应 `SEP`。评分比较 `B3:B14`；目前原始用例 2、3 的同编号输入与答案在 `A3` 上存在不一致，详见实验报告。

### 3. 这个数据集在什么环境下运行？现有 research 框架能否支持？如何支持？

本地使用 Docker Desktop 的 Linux 引擎。每个 trial 在隔离容器中运行 Python 3.12、`openpyxl` 和 LibreOffice Calc；Linux 宿主运行 `research` 的评估入口。框架已有资源包读取、trial 调度、Docker 环境、OpenHands/DSH、trace 和评分接口。个人仓库的适配器将官方原始包转换为 `dataset.json`/`index.json`，准备首个工作簿，在 Agent 结束后重放脚本并比较三个用例。Windows 原生入口因 BenchFlow 的 `fcntl` 依赖不能直接运行，本周使用 Linux 宿主容器。

### 4. 这个数据集为模型提供了哪些工具？能否尽量只用现有工具完成任务？

SpreadsheetBench 原题提供的是表格任务，不自带本实验专用的 skill。当前 OpenHands 配置使用 `terminal`、`think`、`finish`，DSH 配置使用 `terminal`；两者实际处理文件都通过终端中的 Python/LibreOffice 完成。`with-skill` 条件额外提供 SkillsBench 资源包里的通用 `xlsx` skill，模型可通过同一个终端读取 `/skills/xlsx/SKILL.md`；`no-skill` 不提供。无需新增框架工具。提供 skill 不等于模型读过 skill，是否读取应由工具调用 trace 核对。

### 5. 这个数据集采用了哪些评价指标？如何评估任务完成质量？

本周使用原题的 `answer_position` 指定比较区域，LibreOffice 重算输出和参考工作簿后逐格比较计算值，数值按两位小数归一化。记录三个用例各自通过与否、逐例通过率（软分）和三例全对的严格分。另统计 trial 有效评分覆盖率、有效评分中的严格通过率、模型 token 与任务耗时。环境失败和评分器崩溃记为缺失评分；实际比较后不通过才是合法零分。评分器只检查指定区域，不能单独证明工作簿其他区域完全正确。

### 6. 现有 harness 和模型在这些任务上为什么会失败？（skill 角度，harness 指标）

四组预跑显示不同失败机制：`15380` 在两个 harness、两种 skill 条件下都是有效严格分零，但用例 2、3 的同编号输入与答案在 `A3` 月份代码上不一致，不能据此断言模型查找逻辑必然错误；旧 OpenHands `no-skill` 的 `13-1` 与 `17-35` 因评分器访问 `EmptyCell.coordinate` 报错而 `reward=null`，属于评分缺失；OpenHands `with-skill` 的 `17-35` 确实读了 skill，却在 20 次迭代用尽前未写出 `solution.py`，三例输出缺失，得到有效零分。早期 `12307` 的 CRLF 评分脚本故障和 DSH profile 插件缺失发生在接入阶段，也不能算模型零分。

当前 trace 能证明工具调用、文件读取、脚本执行及评分阶段，但不能单独证明模型内部为何选择某种推理。特别是 `17-35` 需要在相同预算下检查产物生成前各步耗时与工具目的，才能判断 skill 内容是否影响作答。四组各只有一轮，本周不作稳定的 skill 或 harness 优劣判断。
