# 框架流程说明

## SkillsBench 入门示例：`3d-scan-calc`

`research` 的 [README 入门示例](https://github.com/LDlornd/research#skillsbench先选一个任务)建议先复制 SkillsBench 的数据集和评估配置，将 `task_ids` 设为 `["3d-scan-calc"]`、`sample_size` 和 `repeats` 均设为 `1`，保持 `conditions = ["with-skill"]`。在 `research` 根目录运行 `python -m evaluation` 并传入数据集、环境、Agent、评估四份配置；先加 `--plan`，应看到该题及 `planned_trials: 1`。`--plan` 只预览配置和任务，不启动 Docker、注册中心或模型，也不创建实验结果。移除 `--plan` 才会执行 trial。这个 SkillsBench 示例用于共同熟悉框架，不作为本组 SpreadsheetBench 的正式评测样本；这里说明的是 README 的操作路径，不声称本组已运行该示例。

| 阶段 | SkillsBench 示例中的实际流程 | 主要结果或检查点 |
| --- | --- | --- |
| 读取任务 | `datasets.skillsbench:load_tasks` 从独立资源包的描述、索引及任务文件读取 `3d-scan-calc` 的指令与元数据 | `--plan` 显示题目和 trial 数 |
| 准备环境 | `prepare_task` 将该题环境、verifier 等素材准备到 trial 目录；`create_environment` 启动隔离的 Linux Docker 环境，`setup_environment` 检查所需 skill 并注入 `/skills` | trial 的任务副本、`task-info.json` 中的 skill 清单 |
| 执行 harness | `evaluation.runner` 将指令、模型、工具、环境和 skill 清单交给 OpenHands runner；Agent 在任务环境里执行工具 | `agent/` 下的运行结果、工具记录及 trace |
| 评分 | `datasets.skillsbench:evaluate` 调用任务容器的原生 verifier，取得 `reward` 和其他指标 | trial 的评分字段与 verifier 日志 |
| 保存结果和 trace | runner 写入每个 trial 的 `result.json`，同时汇总 `manifest.json`、`results.jsonl` 和 `summary.json`；结束后清理容器 | 可按 trial 找回状态、评分、阶段错误和 trace |

五类配置均相对 `research` 根目录：

| 配置对象 | 位置 | 示例中决定什么 |
| --- | --- | --- |
| 数据集 | `config/datasets/skillsbench.toml`（单题示例使用其副本） | `data/skillsbench` 资源包、题目选择、`load_tasks`、`prepare_task`、`setup_environment` |
| 环境 | `config/environments/skillsbench.toml` | Docker 环境工厂、注册中心地址、启动和清理时限 |
| 模型 | `config/agents/openhands.toml` 的 `[model]` | 模型名称、服务地址和密钥环境变量名 |
| harness 与工具 | `config/agents/openhands.toml` 的 `[agent]` | OpenHands runner、recorder、迭代预算及可用工具 |
| 评分器与试验条件 | `config/evaluation/skillsbench.toml`（单题示例使用其副本） | `datasets.skillsbench:evaluate`、`with-skill`、重复次数、通过阈值和输出目录 |

## SpreadsheetBench 本组流程：从入口到结果

`research` 的 `python -m evaluation` 入口读取数据集、环境、Agent 与评估四份 TOML。`--plan` 只读取任务和配置，列出题目、条件、重复次数及计划 trial 数。正式运行时，每个 trial 依次经历任务准备、Docker 环境启动、环境设置、Agent 执行、评分和清理，结果写入独立目录。

本实验的 `datasets.spreadsheetbench:load_tasks` 从独立资源包读取官方题目顺序和三个工作簿用例。`prepare_task` 仅把用例 1 输入复制进任务容器，写入任务要求和评分元数据。`no-skill` 不准备技能；`with-skill` 从本机 SkillsBench 包准备通用 `xlsx` skill，`setup_environment` 注入容器 `/skills`。Agent 通过现有终端工具读取 skill 和工作簿，输出 `solution.py` 与 `output.xlsx`。

Agent 结束后，`evaluate` 才上传用例 2、3 的输入，运行 `solution.py` 得到另外两个输出；参考答案在此后上传给 verifier。评分器用 LibreOffice 重算，按 `answer_position` 比较结果，保存 `cases.json`。`result.json` 保存状态、严格分、逐例结果、各阶段耗时和错误阶段；Agent 目录保留 trace 与 token 用量。容器清理后，生成脚本和输出工作簿仍保存在 trial 产物目录。

## 职责边界与复核点

| 层次 | 本实验中负责什么 | 主要复核证据 |
| --- | --- | --- |
| 独立资源包 | 原始题目、三例输入与参考工作簿 | 包描述、索引、原始文件哈希 |
| SpreadsheetBench 适配器 | 任务准备、skill 条件、用例重放、评分调用 | `task-info.json`、`replay.json` |
| `research` 评估流程 | trial 调度、阶段状态、配置快照、清理 | `manifest.json`、`result.json` |
| OpenHands / DSH | 模型与工具交互 | `agent/trace/`、工具调用记录 |
| Docker 与 verifier | 隔离执行和单元格比较 | 生成工作簿、`verifier/cases.json` |

`reward=0` 只表示已得到有效评分但未通过严格规则；`reward=null` 需要查看 `errors[].stage` 和 verifier 日志。`with-skill` 目录存在只证明技能可用；必须在 trace 中找到读取 `/skills/xlsx/SKILL.md` 的工具调用，才能说模型实际看到了技能正文。首周保持原始失败记录，不覆盖为复评分数。
